# P24 – Exynos8895 UFS true Linux 5.10 platform binding (NO FLASH)

Target: Samsung SM-G955F (dream2lte, Exynos8895), original donor `3ea6f1b4341c0bd9e0e020567fa334da4a1a24c3`, Linux `5.10.262`.

The P23 `ufs_hba_variant_ops` compiled and linked, but `hba->priv` was never populated, so it could not be called successfully by a real UFS platform driver. P24 adds a genuine Linux 5.10 native `platform_driver` with a *distinct experimental compatible* and a `ufshcd_pltfrm_init()` entrypoint, plus a resource binder that constructs the P23 private variant context.

## Implemented

- `research/k510/p24-ufs8895-bind.c` and `.h`: Linux 5.10 platform matcher for **`alice,exynos8895-ufs-research`**, native `ufshcd_pltfrm_init(pdev, alice_8895_get_host_ops())` call and `alice_8895_ufs_bind_host()` to populate `ufs_hba->priv`.
- `research/k510/p24-stage-ufs8895-bind.py`: stages those objects in CI's isolated kernel tree; changes the original *disabled* P4 UFS compatible away from **`samsung,exynos7-ufs`** (which is incompatible for Samsung 8895 PHY); adds validated vendor HCI, UniPro, protector, PMA `0x11124000`, isolation `0x16480724`, coherency `0x11020700`, TCXO `0x11021150` register ranges.
- P24 native UFS callback init binds resource handles if absent and then attempts P23 validation. All P23 readiness and P22 firmware secure-monitor flags remain **false** after allocation, so it fails closed before power, registers or SMC calls.
- Platform probe rejects unless `alice,hardware-audit-passed` is present. The experimental DT deliberately does **not** contain this property and retains `status="disabled"`. Thus the compiled platform driver is never actually matched or allowed to probe in P24 CI.
- No VCC/S2MPS17 GPIO controls are forcefully enabled; clock and supply providers have NOT been added or claimed valid. The binder cannot establish runtime readiness on its own.

## Gaps that block a real boot test

1. Confirm exact physical VCC regulator-fixed GPIO and dynamic PMIC/ACPM/Speedy bus behavior against the working V12R5T kernel on the handset. No surrogate PMIC rails.
2. Proven Linux 5.10 firmware SMC/FMP success, encryption semantics, secure storage, PHY M-PHY/UniPro bringup and correct clock ownership. P24 C compilation only is insufficient.
3. Upstream loader obstacle: prior R1/R2 diagnostic BOOT images actually flashed to SM-G955F hung at static Samsung logo; no reliable 5.10-origin early console/pstore. This needs independent loader instrumentation and memory-handoff evidence. UFS code cannot address failure prior to Linux kernel entry.
4. Complete an independent recovery check with the original user-private 40MiB V12R5T BOOT backup and its exact known SHA-256; do not publish private firmware online.
5. Real boot packaging must be produced from a verified kernel Image, bootloader/uniLoader, board DTBH, compatible ramdisk and a validated restore procedure. This stage publishes **no boot.img**.
