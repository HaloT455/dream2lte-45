# K510 P19 — Port Exynos8895 vendor UFS UniPro host subset to Linux 5.10.262

## Precise scope and evidence

This is a real source-level adaptation of **selected original Samsung 4.4 vendor UFS standard UniPro MIB calibration** and Exynos8895 host hooks to upstream-style Linux 5.10 host variant callbacks. It is NOT the entire 2,420-line vendor 4.4 driver made binary-compatible through fake wrappers.

- Native target: \`drivers/scsi/ufs/ufs-exynos.c\` in genuine Linux v5.10.262.
- Source conversion script: \`research/k510/p19-port-exynos8895-ufs.py\`.
- User-requested CI: https://github.com/HaloT455/dream2lte-45/actions/runs/38055861742
- Verified milestone: **UFS host object \`ufs-exynos.o\` PASS, native PHY object PASS, Exynos8895 research DTB PASS and \`status=disabled\` assertion PASS.**
- Full \`vmlinux\` final linker is a separate CI gate; view workflow for the conclusion. Do not assert PASS without seeing final run status and \`System.map\` symbol check.

## Adapted actual original vendor behavior

- Original Exynos8895 \`phy-init\`, \`post-phy-init\`, \`calib-of-pwm\`, \`calib-of-hs-rate-a\` and \`calib-of-hs-rate-b\` calibration tables are inspected from pinned Samsung SoC DTS.
- Only entries whose **layer is \`UNIPRO_STD_MIB\`** are ported; each address and value is preserved and rendered as strongly typed C arrays. The full original vendor C SHA-256 is recorded in the CI JSON manifest.
- The port invokes real Linux 5.10 \`ufshcd_dme_set()\` from \`exynos8895_ufs_pre_link\`, \`exynos8895_ufs_post_link\` and \`exynos8895_ufs_pre_pwr_change\`, propagating hardware/UIC errors rather than hiding them.
- Modern Exynos UFS variant API remains intact: \`hce_enable_notify\`, \`setup_xfer_req\`, \`setup_task_mgmt\`, \`hibern8_notify\` and PM callbacks are owned by the original Linux 5.10 host implementation.
- A distinct compatible \`samsung,exynos8895-ufs\` is added for the separate host variant; the trial DTS compatible changes but **UFS status stays disabled**.

## Important remaining non-portable pieces

1. Samsung Exynos8895 **PHY PCS/PMA/UniPro debug MMIO** calibration layers have hardware-specific offsets/stride and need actual PHY driver porting; not all vendor PHY tables map to \`ufshcd_dme_set\`.
2. Samsung secure monitor calls \`exynos_smc\` / \`SMC_CMD_FMP_SECURITY\` and SMU initialization must preserve secure-storage behavior, not stub out calls.
3. Samsung Speedy I2C transport, S2MPS17 PMIC rail sequencing and ACPM mailbox firmware handshake have not been run on hardware.
4. Linux 5.10 UFS supplies, phy/PMU DT bindings, clock names, power domains and lane count have not been verified at boot; the trial DTB is not functional storage hardware yet.
5. Android 16 first stage/init, UFS enumeration, /data and One UI 8 startup not tested.

**No flashable \`boot.img\`, Image, or recovery package was generated. Keep V12R5T BOOT, EFS, modem and recovery unchanged.** Only mark true *functional* UFS port when PHY+SMC+PMIC and read-only storage enumeration are verified independently.
