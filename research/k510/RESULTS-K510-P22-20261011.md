# K510 P22 – Exynos8895 UFS Samsung FMP / SMU SMC bridge

## Verified donor ABI

Pinned source `3ea6f1b4341c0bd9e0e020567fa334da4a1a24c3`, file `include/linux/smc.h` and `drivers/scsi/ufs/ufs-exynos.c`:

| Operation | Donor SMC function ID | Argument contract |
|---|---|---|
| UFS FMP security | `0xC2001810` | `(0, ID_FMP_UFS_MMC=0, FMP_DESCTYPE_0=0 or FMP_DESCTYPE_3=3)` |
| UFS SMU init | `0xC2001830` | `(FMP_SMU_INIT=0, ID_FMP_UFS_MMC=0, 0)` |
| UFS FMP resume | `0xC2001840` | `(0, ID_FMP_UFS_MMC=0, 0)` (only if CONFIG_FMP_UFS was enabled) |
| Samsung secure log | `0xC2001860` | `(0, 0, 2)` |

Exynos8895 donor invokes security followed by SMU init on first UFS setup and resume, and FMP resume conditionally. The original `exynos_smc` custom helper is absent from generic Linux 5.10. The latter provides ARM SMCCC via `include/linux/arm-smccc.h`.

## Implemented P22

- `research/k510/p22-ufs8895-smc.c`, `.h`: native Linux 5.10 ARM SMCCC bridge with exact donor SMC command IDs and argument order.
- Unrecognized command or missing firmware/power verification immediately returns a failure.
- Secure FMP init must succeed before SMU init; any subsequent failure leaves both `smu_ready` and `fmp_ready` false.
- If FMP resume returns error, both ready flags are revoked.
- Secure log requires both readiness flags.
- This is a strict compile-only research API: no platform-driver or device-tree binding and **zero clients**; context defaults to all-zero `enable_firmware_calls=false`, `firmware_abi_verified=false`, `ufs_power_verified=false`.
- No firmware SMC is called by CI; the code is compiled and linked only. The existing phone V12R5T, EFS, CP, userdata are not modified.

## Requirements still blocking runtime integration

1. Confirm vendor custom `exynos_smc` return-code semantics and firmware-specific status values against real SMCCC return conventions; do not equate arbitrary nonzero return with successful UFS initialization.
2. Implement and verify the Exynos8895 UFS host-variant init and reset callback sequence, memory-map/control clocks, UFS crypto/FMP descriptor mode, and secure storage handling.
3. Verify ACPM mailbox firmware, Speedy/S2MPS17 regulator ownership, power sequencing and timeouts.
4. Only after these, allow controlled hardware UFS read-only enumeration. No flash, no device-tree enablement in P22.
